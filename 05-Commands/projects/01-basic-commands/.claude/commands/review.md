审查代码并提供反馈。

目标: $ARGUMENTS (未指定时为当前 git diff)

## 审查重点领域

1. **Bugs 和错误**: 逻辑错误、空值检查、边界情况
2. **安全性**: 输入验证、注入风险、敏感数据
3. **性能**: 明显的低效问题、N+1 查询
4. **可读性**: 命名、复杂度、文档需求

## 步骤

1. 如果提供了文件路径，读取该文件
2. 如果没有路径，运行 `git diff` 查看当前更改
3. 根据重点领域分析代码
4. 提供结构化反馈

## 输出格式

```markdown
## 代码审查

### 摘要
[一句话整体评估]

### 发现的问题

#### 严重（必须修复）
- [问题]: [位置] - [简要说明]

#### 警告（应该修复）
- [问题]: [位置] - [简要说明]

#### 建议（最好有）
- [建议]: [位置] - [简要说明]

### 做得好的地方
- [正面观察]
```

## 指南

- 具体说明位置（尽可能提供 文件:行号）
- 提供可操作的反馈
- 不要挑剔风格，除非影响可读性
- 认可你看到的良好模式
